# 저두잇 프로젝트 설계 계획

수정일: 2026-10-11 · 설계안 v2

## 1. 목적과 범위

저두잇은 작은 개인 미션을 지인 챌린지로 연결하고, 참여에 따라 공동 책상이 정돈되는 서비스를 개발한다. 1차 대상은 작은 정리 활동을 함께 수행할 대학생 지인 그룹이다.

핵심 흐름은 개인 정리 체험 → Google 로그인 → 방 생성·URL 초대 → 3일 인증 → 공동 책상과 종료 결과 확인이다. 개인 체험은 공동 활동으로 진입하는 기능으로 제공한다.

| 구분 | 구현 범위 |
| --- | --- |
| 필수 | 정리 개인 미션, 체험 기록 로그인 후 저장, 로그인, 방 전용 닉네임, 방 생성·URL 초대·참가, 3일 인증, 공동 책상, 기록 삭제·계정 삭제 요청, 종료 결과 |
| 기본 개인 미션 목록 | 물·정리·독서·걷기. 공통 완료 체크·메모 구조를 사용하고 일정 점검에 따라 정리·독서로 축소한다. |
| 선택 | 고정 응원 반응, 추가 연출 |
| 후속 확장 | 다른 미션의 챌린지 전환, 5일·7일 기간, 미션별 결과물 |
| 1차 범위 밖 | AI 판별, 푸시, 친구 관계 관리, 자유 채팅, GPS·걸음 수 판별 |

배포 환경은 Flutter Web과 Supabase이며 HTTPS 호스팅은 GitHub Pages를 사용한다. 검증 기기는 PC Chrome과 실제 iPhone Safari이다. 과목의 웹 앱 인정 및 제출 계획 변경 절차는 개발 검증 메모의 확인 항목으로 관리한다.

## 2. 로그인 전후 기록과 초대 흐름

체험 완료 시 텍스트 초안을 브라우저 세션 임시 저장소에 보관한다. 초안에는 미션 종류, 완료 여부·시각, 메모, 다음 행동, 초대 코드, 중복 방지용 초안 ID, 만료 시각을 포함한다. 앱은 생성 후 30분이 지난 초안을 정리한다. 사진은 현재 화면의 미리보기로 사용한다.

Google 로그인 직전에 초안을 저장하고, 같은 브라우저·탭으로 돌아오면 초안을 복원한다. 로그인 성공 후 개인 기록을 서버에 저장하고 방 생성 또는 참가 화면으로 이어간다. 서버에는 사용자와 초안 ID의 유일 제약을 두어 재방문·새로고침으로 기록이 중복 저장되는 것을 방지한다. 초안은 서버 저장 성공 후 제거한다.

초안의 체험 완료 시각과 서버 저장 시각을 구분한다. 개인 체험 초안의 시각은 공동 챌린지 인증 날짜에 사용하지 않는다. 임시 저장이 불가능한 환경에서는 미션 입력에 앞서 로그인하도록 안내한다. 로그인 취소·실패 시에는 초안 만료 전 재시도를 제공한다.

초대는 링크를 기본으로 제공하고 수동 코드는 보조로 둔다. 링크는 앱 주소에 `?invite=ABCD2345` 형태의 값을 포함한다. 초대 값은 OAuth의 인증 코드 파라미터 `code`와 구분한다. 링크를 열면 초대 값을 임시 저장하고 로그인 후 같은 방 참가 화면을 복원한다.

| 상황 | 동작 |
| --- | --- |
| 로그인 상태에서 체험 완료 | 개인 기록 저장 후 방 생성 진입 |
| 같은 브라우저에서 첫 로그인 | 체험 초안·메모·초대·다음 행동 복원 후 저장·진입 |
| 카카오톡 인앱 첫 진입 | 활동 입력에 앞서 외부 Safari/Chrome 열기 안내. 초대가 포함된 주소 복사 제공 |
| 인앱→외부 브라우저 이동 | URL의 초대 값과 공개 미션 종류·다음 행동을 전달. 미션 체험과 메모 입력은 외부 브라우저에서 진행 |
| 임시 저장 만료·차단 | 상태 안내와 미션 재선택 제공 |
| 로그인 도중 방이 만료·마감 | 로그인 후 서버가 참가 가능 여부를 다시 확인하고 마감 안내 제공 |

개인 메모와 사진은 URL에 넣지 않는다. 지원하는 인앱 흐름은 입력 전 외부 이동으로 정하며, 서로 다른 브라우저의 세션 저장소를 공유 기록 저장소로 사용하지 않는다.

방 생성·참가 시 2~10자의 방 전용 닉네임을 입력한다. 방에는 이 닉네임을 표시하며 Google 이름·이메일은 인증 처리용으로 한정한다. 동명 닉네임에는 방 안의 구분 번호를 붙인다.

전환 마찰은 로그인 상태, 첫 로그인, 인앱에서 외부 이동의 세 경로로 측정한다. 로그인한 사용자는 미션 완료 화면부터 방 생성 완료까지 앱 내 4탭·30초를 초기 사용성 목표로 둔다. 첫 로그인과 외부 이동 경로는 외부 화면을 포함한 전체 시간·탭·이탈 지점을 별도로 기록한다.

## 3. 챌린지와 공동 책상 규칙

각 참가자는 같은 개인 구역을 3일간 사용한다. 1일차에는 5분 정리, 2·3일차에는 같은 구역을 5분 정리·유지 관리한다. 그날 수행 후 새로 촬영한 사진 한 장과 완료 체크를 제출한다. 인증은 참가자의 행동 신고와 공유 기록에 기반한다.

하루 한 번을 KST 날짜로 계산하며 날짜별 인증 슬롯은 방·사용자·날짜로 구분한다. 새로운 날짜 슬롯의 첫 인증은 책상 요소 하나를 정리한다. 사진 삭제·인증 취소 후 동일 슬롯을 복구하는 경우에는 기존 보상을 사용한다.

### 보상 산식

시작 당시 인원을 N0, 처음 인증 기회 수를 T0=3×N0로 둔다. 보상은 시작 인원 전원에게 주어진 3일 기회에서 산정한다.

진행 중인 방의 현재 참가 인원을 A, 이탈자들이 이미 획득한 보상 수를 L, 방 전체의 누적 획득 보상 수를 H라고 한다. H는 서로 다른 날짜 슬롯에서 처음 승인된 인증 수이며 이미 획득한 보상은 유지한다.

- 현재 책상 요소 수 T = 3×A + L
- 최초 공동 목표 G = 2×N0
- 진행 중 이탈 시 G = min(기존 G, 2×A + L)
- 공동 목표 달성: 진행 중 A가 1 이상이고 H가 G 이상인 순간 달성 연출과 배지 제공
- 목표 달성 이후에도 새로운 날짜의 첫 인증마다 H가 1 증가하며 T개까지 책상이 더 정돈됨

초기 공동 목표는 전체 인증 기회의 2/3 수준이다. 인원수만큼 총 누락을 허용하는 공동 목표이며, 개인별 최소 2회 인증을 요구하는 규칙과 구분한다. 이탈자는 획득한 기여를 남기고 미획득 몫을 현재 목표와 요소에서 제외한다. 이탈로 목표 인증 수가 증가하지 않도록 이전 G와 비교한다.

| 상황 | 현재 요소 T | 공동 목표 G | 남은 사람들의 최대 획득 수 |
| --- | --- | --- | --- |
| 2명 시작 | 6개 | 4회 | 6회 |
| 3명 시작 | 9개 | 6회 | 9회 |
| 4명 시작 | 12개 | 8회 | 12회 |
| 2명 중 무인증 1명 이탈 | 3개 | 2회 | 3회 |
| 3명 중 무인증 1명 이탈 | 6개 | 4회 | 6회 |
| 4명 중 무인증 1명 이탈 | 9개 | 6회 | 9회 |

예를 들어 4명 방에서 한 사람이 보상 1회를 얻은 뒤 이탈하면 A=3, L=1이므로 T=10, G=7이다. 기여를 포함하여 남은 사람들의 인증으로 목표에 도달할 수 있다.

책상을 주 화면으로 제공하고 ‘정리된 요소 H / 현재 대상 T’와 공동 목표를 표시한다. 기록에서 계산하는 현재 유효 인증 수 C와 관측 참여율 C/T0는 상세 정보·평가 자료로 제공한다. 사진 삭제는 완료 체크를 유지하고, 인증 취소는 C를 줄인다. 획득한 보상 H와 달성 배지는 유지한다.

화면에서 이탈자의 미획득 요소를 제외할 때 이미 정리된 요소를 보존한다. 목표 조정 사실을 방 상태 안내에 표시한다. 시작은 2명 이상으로 하며 이탈 후 한 명이 남은 방은 ‘혼자 마무리’ 상태로 진행할 수 있다. 참가자가 모두 나가면 마지막 책상과 목표·보상을 고정하고 방을 종료한다. 예정 종료 시각 이후에는 T·G·H·획득 배지를 보존한다.

### 방 상태·삭제 규칙

| 상황 | 규칙 |
| --- | --- |
| 모집 | 2~4명, 생성 후 24시간 이내 시작 확정. 만료 시 참가 제한 해제 |
| 시작 확정 | 방장이 참가자 확정. 다음 날 00:00 KST 시작, 3일 뒤 00:00 종료 |
| 실제 시작 전 이탈 | 예약 방 취소, 전체 참가 제한 해제. 남은 사람이 새 방 생성 가능 |
| 진행 중 이탈 | 기존 기여 유지, 미획득 몫 제외, 이후 인증·공유방 접근 종료 |
| 진행 중 방장 이탈 | 같은 이탈 산식 적용. 확정된 시각에 다른 참가자가 계속 진행 |
| 초대 | 보안 난수 8자리. I·L·O·0·1 등 혼동 문자를 제외. 모집 만료·취소·시작 확정 시 마감 |
| 활성 방 | 사용자당 모집·예약·진행 방 합계 1개. 진행 방의 뒤늦은 참가·재참가는 마감 |
| 사진·메모 삭제 | 파일·메모 제거, 완료 체크와 획득 보상 유지 |
| 인증 취소 | 완료 체크 무효와 사진·메모 제거. 현재 인증 수 감소, 획득 보상 유지 |
| 같은 날 재인증 | 진행 중인 당일에 남은 업로드 시도 내에서 동일 슬롯 복구. 하루 최대 유효 인증 1회, 슬롯 보상 1회 |
| 계정 삭제 접수 | 참가 종료 처리, 현재 인증 집계·사진 목록에서 제외, 공유 접근 차단 |
| 기간 종료 | 모든 방에 종료 결과 제공. 종료 시 책상과 배지 보존 |

이탈 후에도 본인 기록 삭제는 개인 기록에서 요청할 수 있다. 이미 지나간 미인증 날짜는 소급하지 않으며, 남은 날짜의 인증 기회와 누락에 따라 목표 달성 여부가 결정된다.

## 4. 사진·개인정보·자정 경계

| 항목 | 기준 |
| --- | --- |
| 개인 체험 기록 | 로그인 후 미션·완료 시각·메모를 DB에 저장 |
| 개인 체험 사진 | 현재 화면의 임시 미리보기 |
| 챌린지 원본 선택 | JPEG·PNG·WebP, 입력 10MiB 이하. iPhone의 실제 사진 선택·디코딩은 작은 검증에서 확인 |
| 서버 저장 사진 | 새 JPEG로 재인코딩, 긴 변 1280px 이하, 결과 1MiB 이하 |
| 메타데이터 | 픽셀로 새 파일 생성, 원본 EXIF·GPS 복사 제외. 위치정보가 있는 시험 사진으로 출력 확인 |
| 업로드 횟수 | 사용자·방·날짜별 서버 발급 업로드 경로 최대 3회. 유효 인증은 하루 1회 |
| 파일 접근 | 비공개 버킷, 현재 참가자와 작성자의 권한으로 인증된 다운로드 |
| 삭제 요청 기한 | 접수 후 7일 이내 실제 파일·개인 기록·계정 삭제 |
| 테스트 보관 | 테스트 사진·인증·메모는 해당 테스트 종료 후 7일 이내 삭제. 최종 테스트 참가 계정·프로필은 최종 테스트 종료 후 7일 이내 정리 |

사진 업로드 화면에는 ‘이 방의 현재 참가자에게 공유’, ‘서버 저장’, ‘개인 기록에서 사진 삭제 또는 인증 취소 가능’, ‘테스트 종료 후 7일 이내 삭제’를 표시한다. 사람 얼굴·주소·문서 등 화면에 담기는 정보를 사용자가 확인할 수 있도록 미리보기를 제공한다.

클라이언트의 압축과 함께 버킷의 JPEG 허용 형식·파일 크기 제한을 적용한다. 업로드 경로는 인증된 서버 요청으로 발급하며, 발급된 당일 경로의 신규 파일 생성 권한만 제공한다. 횟수 제한은 서버에서 계산한다.

삭제 접수 즉시 해당 사용자의 사진을 서버 목록과 새 다운로드 대상에서 제외한다. 파일은 7일 이내 실제로 삭제한다. 새 사진 열람은 사용자 인증과 작성자의 활성 상태를 확인하는 다운로드 방식으로 제공한다. 각 화면은 다시 진입·새로고침할 때 최신 공개 상태를 반영한다. 접수 화면에는 접수일과 처리 예정일을 표시한다.

자정 경계는 업로드를 시작한 날짜에 고정한다. 서버가 업로드 경로를 발급하며 해당 날짜와 만료 시각을 기록한다. 만료는 발급 후 5분 또는 당일 자정 중 빠른 시각이다. 최종 인증 저장 시 서버 시각·경로 날짜·멤버십을 다시 확인한다.

23:59에 시작해 다음 날 서버가 저장을 검증하면 기존 날짜 인증은 실패한다. 다음 날 슬롯으로 자동 이동하는 대신 ‘날짜가 바뀌어 저장되지 않았습니다. 오늘 활동 후 다시 인증해 주세요’라고 안내하고 올라간 파일을 정리한다. 마지막 날에는 종료 안내를 제공한다. 즉시 정리 실패 파일은 24시간 이후 운영 점검에서 제거한다.

최대 사진 용량은 파일럿 9장·본 테스트 18장·동일 규모 재테스트 18장 기준 45MiB이다. 유효 인증 파일과 분리하여 미완료 업로드·교체 파일의 잔여 용량을 점검한다.

## 5. 서버·운영 구조

방 참가·시작·인증·취소·이탈·삭제 접수는 사용자 권한을 확인하는 DB 함수에서 처리한다. 인증 슬롯의 유일 제약과 방 행 잠금으로 동시 요청을 처리한다. 슬롯의 보상 지급 여부를 저장해 취소·복구 시 중복 보상을 방지한다.

현재 유효 인증 수, 누적 보상, 이탈 기여·목표 조정은 같은 트랜잭션에서 처리한다. 계정 삭제 시 방에 남기는 값은 개인 식별 정보와 분리된 기여 합계·목표·획득 보상이다. 참가자의 닉네임·계정·개별 기록은 삭제 대상으로 관리한다.

운영 DB 함수는 서버 시각을 전달받아 같은 KST 계산 규칙을 사용한다. 관리자 SQL 테스트는 공개되지 않은 내부 계산 함수에 시험 시각을 전달한다. 일반 앱 호출에는 서버 시각을 적용한다. Supabase 프로젝트는 1개로 운영하고 SQL 변경 파일을 순서대로 관리한다.

테스트·시연 전날에는 로그인, DB 읽기, 업로드·열람·삭제를 확인한다. 매주 미완료 업로드를 정리하고 삭제 요청 기한과 테스트 보관 기한을 점검한다.

## 6. 조사와 검증

개발 전 인터뷰에서 같은 진행 상태의 숫자 화면과 책상 화면 시안을 비교한다. 인터뷰 5명 중 3명은 1주차, 나머지 2명은 3주차 초에 수행하여 책상 구현 전에 비교를 마친다. 시안 제시 순서와 선호 이유를 기록한다. 시안 선호는 표현 선택 자료로, 구현 후 평가는 실제 조작·행동 자료로 구분한다.

6명 테스트는 지인 3명씩 2개 방으로 진행한다. 모집 경로·개발자와의 관계·인터뷰 중복 여부를 가명으로 기록한다. 관측 참여율은 시작 인원×3을 분모로 유지하고, 목표 조정·이탈·누락·취소와 관찰 시점을 함께 기록한다.

운영자는 테스트 3일간 매일 19:00 KST에 6명 모두에게 동일한 리마인드 문구를 한 번 제공하고 발송 시각·누락 여부를 기록한다. 결과는 리마인드가 제공된 조건의 참여 관찰로 평가한다.

조사 신호에 따라 진입 문구·배치를 수정하고, 사진 공유 부담이 주요 장애로 나타나면 사진 선택형 또는 체크·메모형 인증안을 검토한다. 공동 활동 의향이 낮으면 추가 기능보다 핵심 시안 보완을 우선한다. 사진 관련 범위 변경은 제출 계획 변경 절차와 함께 확정한다.

정규 사진 삭제 UI와 통합 기록 삭제 UI 중 실제 채택한 방식을 기능 목록에 표시한다. 통합 시에는 기록 삭제의 현재 집계 감소와 보상 보존을 안내한다.

개발 완료는 확정된 MVP 기능 목록 완료, 기능 시나리오 F01~F10, 권한 R01~R06, 시간 T01~T06, 사진·기기 P01~P04의 통과, 실제 3일 파일럿 수행, 삭제 운영 확인으로 정의한다. 세부 실행·결과 기록 양식은 개발 검증 메모로 관리한다. 채택 범위 변경 시 해당 항목과 제외 사유를 함께 갱신한다.

사용자 선호·참여율은 제품 가설의 관찰 결과로 보고하고 개발 완료 판정과 구분한다. 필수 권한·시간·개인정보 처리는 컷 이후에도 유지한다.
